1. **协议组 6:0 胜出**：总分 **86.5 / 73.0**（满分 90/组），均分 14.42 vs 12.17（+2.25/题，+18.5%）。

## 二、实验设计

| 项 | 设计 |
|---|---|
| 问题 | `D:\zotero\eval_report\questions.json` 的 6 个真实研究问题（q1–q6） |
| 证据 | 每问用当前插件（v0.1.21 / 52,298 块索引）实时检索一次 `k=8&mode=hybrid`，**两组拿同一份 JSON**（含 `evidence` 与 8 条 `results`） |
| A 组（朴素） | 只要求"基于这些检索结果回答 + 给出依据来源与页码"，无任何判读规则 |
| B 组（协议） | 同证据 + `AGENT_PROTOCOL.md` §3–§6（evidence 判读、覆盖映射表分级、多源规则、作答三档措辞、局限要求） |
| 盲评 | 3 名评审各评 2 题；每题的甲/乙标签**随机化**（种子 20261023），评审不知道分组；给出证据 JSON 供核对引用真伪与页码 |
| 评分 | 5 维 × 0–3 分（贴合/多源/溯源/局限/增量），总分 15；0.5 分内判平局 |
| 隔离 | 两组都只读同一证据文件，禁止检索/联网（确保"证据相同"） |

### 3.3 双方的具体错误（诚实记录）

**A 组（朴素）典型错误 —— 外推与升格**
- q3：把 `HBVDZ6UJ` 首页无标引的"儿童对高饱和反应比成人高 30%"当实证引用；漏掉 `RIN36VNR` 页 2「亮度对唤醒效应更强」的反证。
- q4：把成人/办公环境结果直接外推到小学教室；对证据里没有的"饱和度"作推断。
- q2：把 ADHD 儿童（n=18）样本升格为普通儿童"应用层面"结论；未标注 `IML7LTMS` 为首页摘要段。
- q1：未标明 `L37Q9F8D` 序列系 Jung/Kim 等二手转引。

**B 组（协议）典型错误 —— 多为元数据/转引细节**
- q1：把 `L37Q9F8D` p3 多算作"高饱和偏好下降/一致性上升"的支持（该段无此内容）。
- q2：称"粉/紫偏女、红偏女三源一致"，但 `IML7LTMS` 明说男孩更常选红，与自身前句矛盾。
- q5：把 `9KBXTJ5H`"大面积家具宜低饱和柔和暖色"扩写为"家具、墙面"。
- q6：4 处元数据小错（样本描述、"36:491–496"归属、"显著"强于原文"差很多"、国别为推断）。

> 也就是说：协议把"证据边界"这一层做对了（这正是历史 q4 翻车的原因），但**不保证每个细节都对**；引用前仍应核对原文。

## 四、这次实验改变了什么判断

**原假设**（交接文档 T3）：「召回已够好，但 agent 没充分利用召回」——历史 A/B 中 6 题各只引用 1 篇（25 篇独立文献仅引 6 篇，24%）。

**本次发现**：在**当前接口**（k=8 + `evidence` 块 + `hints`）下，同一个模型族在朴素提示下就会用 ~6 篇、页码也标对。历史"只引 1 篇"至少部分来自旧接口（v0.1.8 返回**扁平数组**、无 `evidence`、k=5），不能直接归因于 agent 懒惰。

**因此协议的正确目标不是"读多"，而是"分级 + 降级 + 局限"**：
1. 区分「直接/间接/背景/无关」——防止排第 1 的综述段被当结论（历史 q4）；
2. `hints`/`pageSource`/`role` 的降级标注——防止把缓存回填段当有页码证据、把首页段当研究结果；
3. 外部效度必须交代——防止"大学生 → 小学生""办公空间 → 走廊"的静默外推。

## 五、局限（必须一起读）

1. **n=6，单次作答**：方向性证据，不是统计显著结论；未做重复采样，未算置信区间。
2. **A 组不是历史原样**：A 组提示词要求"列出依据来源"，因此多源/溯源两项被抬高；若 A 组就是历史那种"最小成本"提示，差距会更大，但**本实验不能证明这一点**。
3. **作答与评审同族模型**：评审可能偏好与协议同构的结构（如显式的局限段）。缓解：评审看到的是打乱后的甲乙、且被要求核对引用真伪；但无法完全排除风格偏好。
4. **成本上升**：B 组答案 1626 汉字 vs A 组 740（+120%），主要是覆盖映射表；**检索成本不变**（同一份证据）。
5. **未验证**：协议 §5 的查询改写策略（本次固定证据以隔离"判读"变量）；协议在真实多轮会话、跨语言查询、长文档场景下的效果。
6. **判分文件修复说明**：3 个 verdict JSON 的中文键在子代理写盘时被编码破坏，按任务规定的字段顺序做了位置映射修复（`repair_verdicts.py`，**只改键名不动数值**）；修复后的每题总分与 3 名评审通过消息报告的成绩逐一核对一致。
